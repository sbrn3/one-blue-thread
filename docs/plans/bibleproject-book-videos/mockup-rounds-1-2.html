E · As built (recommended)

This direction adds no new visual idea. Every element is an existing style from the shipped app, and each class in this file names its source StyleSheet. The overview link is the existing link button. Dismissal asks the way it already asks about marks: a mono question with a button. Writing happens in a bottom sheet that looks exactly like the verse sheet. The reader's lines use the memory library's italic passage style. The history book page is a memory-library-style screen, with the library's confirm-before-delete.

B · Card

An explicit, bounded object. The takeaway lives in a hairline panel (radius.panel 12) with its reference as a header, a multi-line field and a Save pill. History shows one card per line with Edit and Delete visible. The clearest affordances, but the heaviest, and it adds a new "panel" register to Dismissal.

C · Thread

Takeaways sit on the cloth metaphor. In Dismissal there is only a dashed "keep a line" prompt until you tap it, so nothing is asked of you by default. A saved line shows as a quote with a madder rule (a mark you made). History draws the book as a vertical thread, with a chapter knot at each chapter and a madder bead per line. The most on-brand and the most build work: it needs a custom SVG rail.

D · Selvedge ties (level-up, recommended)

Takeaways don't get their own timeline, because the bolt already is one. Each day with a line gets a madder tie hanging off the cloth's right selvedge at that day's row. The same tie leads each line underneath, so the cloth and the lines read as one object. In Dismissal, a loose warp-coloured tail invites a line. Saving pulls it taut into madder, and today's row gains its tie. See level-up.md.
