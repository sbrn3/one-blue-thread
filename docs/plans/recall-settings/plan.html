Problem & Intent

Status, owner & next action

Approved 2026-10-07 by the owner, including build through merge and deploy. Owner: the app owner. Next action: run S01 on feat/recall-settings in the thread-recall-cloze-ladder worktree.

Outcome and constraints

Memory passages work like an Anki deck you control. Today a passage is chosen once, at the end of a book, one per book, and is visible only on the day it is due. The reader can't fix a range picked too short or too long, can't start over, and can't learn a passage they didn't read that day. After this change the knot has a memory library where you see every passage, add any passage from the Bible, edit its verses, start it over, delete it, and review on demand, plus a daily cap you set. Scheduling stays Leitner and the cloze ladder from v0.8.0 is unchanged.

The experiments run in parallel and stay clean. Library actions never touch E9, the next-day probe, which also stops preferring marked verses. Passages added with the picker are not E4 marks. Hard rules: the migration is additive, events are append-only, there is no Math.random, /src/memory never imports /src/lab, and no memory action touches seal, streak, weave or dose.

Scope and non-goals

In scope: the library sheet (direction A), the passage picker and range editor, add, edit, start over, delete, review now, practise, the marked list with "Learn this", the daily cap (1–10, default 2), an optional multi-pick book end, the removal of the one-per-book rule, the probe no longer using marks, and migration V13 (passages.source). Non-goals: see Requirements → Out of Scope.

Requirements (confirmed)

User stories

  1. As a reader, I want a "Memory" row in the knot's everyday tier that shows how many passages are due and opens my library, so that my passages are always one tap away.
  2. As a reader, I want to see every passage I'm learning (reference, a line of text, ladder step and when it's next due, due first) and every verse I've marked but not learned, so that I know what I'm memorising.
  3. As a reader, I want to add any passage from the Bible by picking a book, a chapter and then the first and last verse, with a preview, so that I can learn something I didn't read today.
  4. As a reader, I want to change a passage's verses when I picked too few or too many, keeping its schedule with the ladder stepped back one, so that a correction doesn't wipe my progress.
  5. As a reader, I want to start a passage over (box 1, step 1, due today), so that I can relearn one I've lost.
  6. As a reader, I want "Learn this" on a marked verse, adjusting its range first, so that marks become passages whenever I choose.
  7. As a reader, I want to delete a passage after confirming, so that the library holds only what I want.
  8. As a reader, I want "Review now" to take me through everything due, including what's past today's cap, with the same cloze cards and grades as the reading screen, and each grade reschedules, so that I can catch up when I have time.
  9. As a reader, I want to practise any single passage from its page, so that I can rehearse before it's due.
  10. As a reader, I want to set how many due passages the reading screen shows each day (1–10, default 2), so that recall fits my time.
  11. As a reader, I want changes I make in the library (cap, adds, grades, deletes) reflected on the reading screen the same session, so that the two never disagree.
  12. As a reader finishing a book, I want to learn none, one or several of that book's marks and then tap Done, so that the book end is an offer, not a single forced choice.
  13. As a reader, I want the next-day probe to ask about a seeded span of what I read, regardless of my marks, so that it stays a fair test separate from my memory work.
  14. As the lab, I want E9's arm assignment unchanged and every probe still recorded, so that the experiment stays reconstructible. The second outcome boundary (marks no longer favoured) is recorded in the journal.
  15. As the lab, I want E4's marks-per-chapter to count only verses marked while reading, so that library use doesn't distort the reading-depth signal.
  16. As a reader upgrading from v0.8.0, I want every existing passage, mark, box, rung and due date unchanged, so that nothing is lost.
  17. As a reader restoring an older backup, I want it to restore cleanly into the new schema, so that safekeeping keeps working.
  18. As a reader, I want a clear message when I try to add or edit into a passage I'm already learning, or an invalid range, with nothing saved, so that I don't get duplicates.
  19. As a reader using a screen reader or large text, I want every control at least 44pt and labelled, the cap stepper adjustable, and verses announced with their selection state, so that the library is usable without sight or fine motor control.
  20. As a reader offline or on a network translation, I want the picker to load chapters from my current translation and show "Retry" if one fails, with the bundled WEB always working, so that adding never silently breaks.
  21. As a reader, I want no library action or grade to affect my seal, streak, weave or dose, so that memory work stays consequence-free.

Out of Scope

  • Anki's scheduler (ease factors, SM-2) — Leitner stays (§21 and the 2026-10-02 decision).
  • Ranges spanning chapters; tags or decks; import/export of passages beyond the existing backup.
  • Editing a passage's text or translation; per-passage translation.
  • A user control over the probe or any experiment — experiments stay parallel and not user-tuned.
  • Undo after delete (the confirm step is the guard; the event log keeps the record).

Verification

Automated gate: npm test and npm run typecheck, plus CI's APK build. This change includes a migration and a destructive action, so the checklist below is mandatory. Run it on a dev build installed over v0.8.0.

  • Install over v0.8.0 with existing passages → every passage keeps its range, step and due date; the Memory row shows the correct counts.
  • Open Memory from the knot → the list matches the mockup (cap, Review now, Learning due first, Marked, Add).
  • Add Psalm 23:1–3 → it appears due today; the reading screen's recall zone shows it after closing the knot.
  • Add the same range again → a refusal message, and nothing is added.
  • Edit a passage's range → it keeps its due date and its step bars drop one.
  • Start over → step 1, due today.
  • Delete → confirm → it's gone. Cancel → nothing changes.
  • Set the cap to 4 → the reading screen shows up to 4 due; reopen the app → it's still 4.
  • Review now → grade every due card → the list shows their new due dates.
  • Learn this on a mark, after changing its range → it moves to Learning with the new range.
  • Finish a book with 3 marks → learn 2 → Done → "Now close the app" appears; the third mark stays in Marked.
  • Picker on NIV/ESV offline → a chapter fails to load and shows Retry; switching to WEB works.
  • Export a backup, unravel, then restore → the library and the cap come back.
  • TalkBack: the Memory row, stepper ("2, adjustable"), verse selection ("Verse 16, selected") and Delete confirm are all announced.
