Problem & Intent

Status, owner & next action

Awaiting approval. Owner/trigger: reader feedback on issue #30 plus the owner's own grill (grill-summary.md). Next action: approve this plan and authorize a branch/PR policy (see gates), then run S01.

Outcome and constraints

A reader should be able to find the settings sheet without knowing what "Knot" means, and find things inside it where they expect them. The sheet's order must not change depending on state. A reader can also change translation from the sheet, which onboarding already promises ("add a translation any time from the knot") and the code does not deliver. Constraints: offline-first (WEB always works), no real keys in tests or repo, keys stay in SQLite meta, 44pt targets, reduced motion honoured, hard rules in AGENTS.md untouched.

Scope and non-goals

In: (a) gear-icon opener with an attention dot; (b) knot sheet re-ordered around the user stories, with Safekeeping and Support no longer promoted or auto-expanded, and backup demoted to a quiet row that never raises a dot or marker; (c) the parked knot-translation-switch plan, absorbed, as the first row of the Preferences group. (d) bug fixes the owner reported against the latest build: Start over does not work, and an edited cue (practice prompt) does not seem to save; (e) a "Report a problem" link to a new GitHub issue. Out: night mode and its Appearance row (own grill, no dead rows); onboarding wording changes; multi-translation; backup encryption of keys.

Requirements (confirmed)

User stories

  1. As a reader, I want the settings control to be a recognisable gear, so that I can find it without knowing the word "Knot".
  2. As a reader, I want the gear to show a small dot only when Support (something is genuinely wrong) needs attention; backup status never lights it, because backup is not a priority for me. A screen reader gets the same information in words.
  3. As a reader, I want the sheet to look and order itself the same every time I open it, so that I can learn where things are.
  4. As a reader, I want a Support section that needs attention to stay in its normal place, collapsed, with a visible marker, so that it neither moves nor hides what I came for.
  5. As a reader, I want my weave, my cue, and my reading history immediately visible, so that the daily things take no digging.
  6. As a reader, I want a paused-notifications banner with a Resume button when paused, so that I can turn them back on.
  7. As a reader, I want to switch between tap and hold sealing, so that a gesture that fails for me is not a dead end.
  8. As a reader, I want to set up or check my accountability partner and check-in.
  9. As a reader, I want to freeze adaptive notification timing.
  10. As a reader, I want to browse study material for my current book.
  11. As a reader, I want to confirm my history is backed up.
  12. As a reader, I want "Starting over" to be last in its group, so that a destructive control is not next to everyday ones.
  13. As a reader, I want the origin story available under About.
  14. As a reader, I want diagnostics to stay out of the way until something is wrong, then be easy to find because the gear and its row are marked.
  15. As a reader, I want to choose between the World English Bible, NIV and ESV from the sheet, with the bundled text named in full.
  16. As a reader, I want a pasted key proved by a live check before it is saved, and a failure to keep my current translation and show the error, so that I never believe I'm in NIV while reading WEB.
  17. As a reader, I want a key I already pasted kept per provider, so that switching back doesn't mean pasting again.
  18. As the lab (silent actor), I want a translation change logged as a confound, so that days around it are reported but excluded from verdicts.
  19. As a reader switching mid-day, I want today's portion reloaded and restarted at sitting 1, so that re-reading, never skipping, is the failure mode.
  20. As a reader, I want Start over to actually work (hold to unravel erases everything and restarts the app), and to be told plainly if it can't, so that a failed erase is never silent.
  21. As a reader, I want a cue I edit in the knot or on the arrival screen to show the new text in both places and to survive the next edit, so that a change never silently reverts.
  22. As a reader, I want a "Report a problem" link under About that opens a new GitHub issue in my browser, carrying only the app version, so that I can log a bug in seconds without exposing my reading data.

Out of Scope

  • Night mode / Appearance row: needs its own palette design (per-token contrast, book dyes on a dark ground). Reserved in the layout, not built.
  • Onboarding translation wording changes: the app is personal-use for now.
  • Memorised-verse wording shifting under a mid-trial switch: the confound flag covers the data; the reader experience stays deferred (as in the translation plan).
  • Encrypting API keys inside backup exports (pre-existing exposure).

Testing Decisions

  • The suite is Vitest in node with no component renderer (AGENTS.md). UI changes are guarded by source-walking contracts in test/ui-contracts.test.ts: no promoted in the knot, no "Knot" opener label, TranslationSection on the interactive allowlist.
  • Logic is tested with the existing patterns: test/confound.test.ts (one new case), test/esv.test.ts (fake fetchFn), new test/translationService.test.ts (openTestDb() + migrate(db) + a fake provider).
  • Not unit-tested: the gear's appearance, safe-area placement, the sheet's visual order, and live NIV/ESV calls. Those are owner spot-checks and the S05 gate.
