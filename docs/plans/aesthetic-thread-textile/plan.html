Outcome and constraints

Underlying need: Thread is a singular, private, offline devotional object, but it is dressed in the default minimal-SaaS uniform. Its entire vocabulary — thread, weave, knot, seal, cue — is textile, and none of that is in the visual language. The app icon is a blue chevron carrying a gradient and a drop shadow (both forbidden by src/ui/tokens.ts's own comment) with construction guides still baked into the PNG.

Desired outcome: one coherent identity — "The Loom" — across the icon, the public demo, and the three in-app surfaces where the thread is visible.

Hard constraints, verified against AGENTS.md §13.6:

  • This plan writes no events, adds no migration, and touches no PRNG / trial_seed path. It is presentational plus one additional meta read (book_started_local_date, already written by src/state/session.ts).
  • No Math.random(). Thread waviness and per-book dye assignment are deterministic functions of position and canon index — enforced by a new unit test.
  • No new runtime dependency and no new typeface. react-native-svg 15.15.4 and react-native-reanimated 4.5.0 are already in package.json. Icon rasterisation uses headless Edge/Chrome (both verified present) — a build-time invocation, not a dependency.
  • Import boundaries hold. test/boundaries.test.ts forbids /src/lab → /src/ui; new files live in /src/ui and are imported only by /src/flow, which already does so.
  • Privacy: synthetic data only in every mockup and screenshot. No real reading history, cue text, or partner contact.
  • Reduced motion must be honoured by every new animation (Reanimated useReducedMotion(), already the pattern in SealZone.tsx and ThreadRail.tsx).

Scope and non-goals

In scope: (1) rescue + land the completed demo restyle; (2) the app icon and its five PNG outputs (splash-icon.png dropped — orphaned, app.json has no splash config); (3) the tokens.ts palette migration including the eight hardcoded #EEF0FF sites; (4) a shared cloth renderer with a tested pure-geometry core; (5) WeaveZone → the current book as a bolt of cloth; (6) ThreadRail → a loom rail with a fell line; (7) SealZone → a shuttle pass.

Requirements (confirmed)

User stories

  1. As the reader, I want the app icon on my home screen to look deliberate and hand-made, so that opening Thread feels like picking up a made object rather than launching a utility.
  2. As the reader, I want the icon to be legible at 32px in a crowded app drawer, so that I can find it without reading the label.
  3. As the reader on Android, I want the icon to work as a monochrome/themed icon, so that it matches my system theme without turning into a blob.
  4. As the reader, I want the app's colours to feel like dyed cloth rather than software chrome, so that the reading surface feels calm and physical.
  5. As the reader, I want no screen to show a muddy or clashing blue tint after the palette changes, so that the app never looks half-migrated.
  6. As the reader opening the app, I want the left rail to read as warp threads being woven as I scroll, so that my progress through today's reading is shown as an advancing edge rather than a progress bar.
  7. As the reader at the top of an unread chapter, I want the rail to show bare, slack warp below the fell line, so that what is ahead of me is visibly not yet done.
  8. As the reader pressing and holding to seal, I want the weft to visibly pass across the warp, so that sealing feels like completing a physical action.
  9. As the reader who releases the hold early, I want the weft to retract and nothing to be recorded, so that an accidental touch never logs a day.
  10. As the reader who has sealed, I want the completed pass to lock into the cloth, so that the gesture has a visible, permanent result.
  11. As a keyboard or switch-control user, I want the seal control to be operable without a press-and-hold gesture, so that I can seal a day at all.
  12. As the reader who has sealed today, I want the weave zone to show the book I am currently reading as a bolt of woven cloth, so that I see my progress through this book rather than an arbitrary calendar month.
  13. As the reader, I want the bolt's width to be the book's chapter count, so that a long book is visibly a wider piece of cloth than a short one.
  14. As the reader, I want the bolt's length to be the days elapsed since I started the book, so that the cloth records real time and not just my successes.
  15. As the reader who missed a day, I want that day to leave an open row of bare warp in the cloth, so that the gap is visible and honest.
  16. As the reader who missed several days, I want the warp across the gap to go slack and drift, so that a lapse reads as open cloth rather than as a scored failure.
  17. As the reader returning after a lapse, I want the cloth to carry a permanent set mark where I picked up again, so that the record is truthful without being punitive.
  18. As the reader of a very long book (Psalms, 150 chapters), I want the bolt to stay legible on a phone screen, so that the weave zone is never an unreadable smear.
  19. As the reader of a one-chapter book (Jude), I want the bolt to still read as cloth and not as a single line, so that short books are not visually degenerate.
  20. As the reader, I want each book to carry its own natural dye, so that successive books are visually distinct from one another.
  21. As the reader, I want the same book to always take the same dye, so that the colour is a stable property of the book and not a random per-session choice.
  22. As the reader with reduced motion enabled, I want the cloth to render at its finished state with no weaving animation, so that the app respects my OS setting.
  23. As the reader using a large OS font scale, I want the weave zone's labels to reflow without clipping the cloth, so that the screen stays usable.
  24. As the lab (a silent actor), I want the E3 streak-visibility experiment to keep working unchanged through the weave zone's rewrite, so that a concluded experiment still governs whether a count appears.
  25. As a future maintainer, I want the cloth geometry to be pure, deterministic and unit-tested, so that the rendering can be reasoned about without a device.
  26. As a reviewer, I want each surface to arrive as its own PR, so that a regression can be traced and reverted per surface.

Testing Decisions

  • The seam that gets tested is src/ui/cloth.ts — pure geometry, no React, no react-native-svg import. This is the only genuinely testable part of the change and it carries all the real logic: support/slack distances, plain-weave alternation, the warp-sett rule, and path determinism.
  • Also tested: src/ui/dye.ts — that every one of the 66 canon books maps to a dye, that the mapping is stable across calls, and that it uses no PRNG.
  • Prior art to follow: test/boundaries.test.ts for the file-walking/import-assertion pattern; the existing pure-logic suites in test/ (Vitest, node environment, better-sqlite3 standing in for expo-sqlite) for structure and naming. One file per area — so test/cloth.test.ts.
  • Deliberately not unit-tested: anything requiring component rendering. AGENTS.md is explicit — the suite is pure logic and simulation only, with no Testing Library and no component rendering. WeaveZone, ThreadRail and SealZone are therefore verified by typecheck plus a dev-build glance, not by Vitest.
  • Also not tested: exact SVG path strings (brittle and meaningless); the visual appearance of slack; the PNG pixel output of the icon.
  • Must stay green: test/boundaries.test.ts — the new /src/ui modules must not be reachable from /src/lab.
  • Manual, on a dev build: the two OPEN gates above — the Psalms/Jude sett extremes, and whether #8F8779 warp reads correctly on a real screen.

Intent

The reading surface should feel like a working loom, mid-project — warm, taut, slightly irregular, unmistakably being made by hand and not yet finished. This is an extension of the existing single visual register (one accent, flat, hairline), not a new pattern: the same restraint, with the accent re-cast as dyed thread and the one decorative element in the app re-cast as cloth.

Hygiene

Every value comes from src/ui/tokens.ts after Slice 3. New tokens: color.warp #8F8779, color.dyeSoft #E7E9F4, color.madder #B5482F, and dye[] = indigo #2E3A8C · madder #B5482F · walnut #6B4E37 · weld #A8761E · woad #3E6B5A · cochineal #8E2F4A. Thread has one visual register and no theme switcher, so there is no cross-theme matrix to satisfy.

Details

Pressed/active: the seal's weft advances under the finger and retracts on early release (existing behaviour, new mark). Loading: none — the weave zone reads from SQLite synchronously, as today. Empty: day 1 of a new book is a fully-dressed loom with bare warp and no weft — a deliberate, meaningful empty state rather than a blank box. Entry/exit: the weave zone mounts after a seal in the flow and is reachable any time from the knot, independent of today's seal (Flow.tsx:40–43, Knot.tsx:122) — the un-sealed knot path must render correctly. Error: a book with an unknown chapter count (bundledChapterCount returns 0) falls back to the MIN_COLS ribbon rather than dividing by zero. Focus: SealZone.tsx:123–142 already exposes an accessible Pressable when sealMode === 'tap' || screenReaderEnabled || reducedMotion. The real gap is that the fallback is gated on a screen reader being detected, so a keyboard/switch user without one still gets only the gesture — that is what Slice 7 closes. Font scale: labels sit above the cloth in a normal flow, so a large scale pushes the cloth down rather than clipping it. Reduced motion: cloth renders finished; no shuttle, no settle.

/** Rows from each day to the nearest woven day. 0 = has a weft. */
export function supportDistances(sealed: boolean[], slackCap = 4.5): number[] {
  const n = sealed.length;
  // Smart Review [MED]: seed with slackCap, NOT Infinity. An all-unsealed book
  // would otherwise leak Infinity into path coordinates and produce "NaN" in
  // the `d` attribute. Clamping here is what makes the named test pass.
  const d = new Array(n).fill(slackCap);
  for (let j = 0; j < n; j++) if (sealed[j]) d[j] = 0;
  for (let j = 1; j < n; j++) d[j] = Math.min(d[j], d[j - 1] + 1);
  for (let j = n - 2; j >= 0; j--) d[j] = Math.min(d[j], d[j + 1] + 1);
  return d;
}
